     - Налог рассчитывается от выручки Заказчика по формуле: $\text{НДС} = \text{Выручка} \times \frac{\text{Ставка}}{100 + \text{Ставка}}$ (для 5%: $\times 5/105$, для 22%: $\times 22/122$, для К10: 0 ₽).

     - В конце пайплайна Express в `server/index.js` внедрен централизованный middleware обработки ошибок `(err, req, res, next)`.
     - В production-режиме клиенту отдается строго стандартизированный JSON `{ error: err.message }` без внутренних путей на диске, фрагментов SQL-запросов и стека вызовов Node.js.
     - Для неизвестных путей `/api/*` возвращается стандартизированный 404 JSON-ответ.

2. **П.61: Защита сетевого контура и заголовки безопасности (HTTP Security Headers)**
   - *Что сделано:*
     - Добавлены заголовки:
       - `X-Content-Type-Options: nosniff` (запрет MIME-sniffing);
       - `X-Frame-Options: SAMEORIGIN` (защита от Clickjacking);
       - `Referrer-Policy: strict-origin-when-cross-origin` (защита от утечки URL в реферере);
       - `Permissions-Policy: camera=(), microphone=(), geolocation=(self)` (отключение неиспользуемых браузерных API);
       - `Strict-Transport-Security: max-age=31536000; includeSubDomains` (принудительный HTTPS при работе за обратным прокси Nginx / Caddy / Cloudflare).

3. **П.62: Отказоустойчивость пула БД и безаварийное завершение (Graceful Shutdown)**
   - *Что сделано:*
     - В `server/config/db.js` пул PostgreSQL защищен от исчерпания соединений (`max: 20`) и зависших запросов (`connectionTimeoutMillis: 5000`).
     - Событие `pool.on('error')` перехватывает сбои неактивных клиентов без аварийного краша Node-процесса.
     - В `server/index.js` перехватываются системные сигналы остановки контейнера / сервиса (`SIGTERM`, `SIGINT`): сервер плавно завершает активные HTTP/WebSocket соединения, закрывает транзакции пула PostgreSQL и безопасно завершает процесс с 10-секундным защитным таймаутом.

4. **П.63: Горячее резервное копирование и диагностика здоровья (Backup & Health Check)**
   - *Что сделано:*
     - Разработан сервис `server/scripts/backup_db.js`, выгружающий все критические таблицы (заявки, договоры, ДС, контрагенты, специалисты, ТМЦ, субподряды, доверенности) в структурированный JSON с автоматической ротацией.
     - Проведено успешное боевое тестирование: снимок базы `backup_stockeasy_2026-10-15T06-44-45-324Z.json` (56 МБ, 8 412 заявок, 1 061 договор, 300 ДС, 674 контрагента, 188 специалистов) сгенерирован за 1.2 секунды.
     - Создан API-модуль `server/routes/admin.js`, позволяющий администраторам и директорам отслеживать метрики здоровья системы (`/api/admin/health`) и создавать бэкапы перед массовым импортом реестров прямо через защищенный интерфейс.
